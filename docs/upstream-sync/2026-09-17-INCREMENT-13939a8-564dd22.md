## 3. 最终功能链，而不是按提交机械复制

### 3.1 可先做的小批次

1. **批量状态依赖 waiting（68）**：先复现。若存在，修前端计划与服务端准入展示；不自动采纳、锁定或续跑。
2. **Provider 凭证空白/非法头错误（78 的独立部分）**：用合成 Key 覆盖保存、冻结任务、执行和错误持久化，确认现有脱敏边界后再改。
3. **LAN HTTP 请求 ID（79）**：通用 helper + 三处现有调用回归，不等待导入/助手。
4. **手工画布连线删除（58）**：功能不大，但必须走 graph 对象 CAS/负责人权限，属于独立协作批次。
5. **编辑器工具栏对齐（72）**：66 的业务逻辑已经满足，只补当前实际可见布局问题。
6. **创建页与作品库界面（62/63/71）**：可按“创建页”和“作品库”拆成两个纯界面批次。

### 3.2 应作为连续能力实现的较大功能

- **智能文档导入：61 → 74 → 75 → 78（模型确认）→ 79（请求 ID）→ 80。** 建议按可验收闭环拆为：
  1. 安全上传/本地抽取/规则预览，不调用 AI；
  2. 平台文本模型显式选择、后台分析、只返回原文边界的候选；
  3. 权限/CAS 下原子确认到原著或正式剧本；
  4. 恢复预览与完成提醒。
  每步都要真实 PostgreSQL 测试；不得在上传后自动发生付费调用。
- **Production 回收（64A）** 与 **共享视觉风格补齐（64B）** 是两个独立任务，不共享迁移授权。
- **画布剧本输入（59）** 应先于 **构图 helper 节点（60）**；两者都依赖 graph 对象写入与任务冻结，但不要求建通用“任务平台”。
- **AI 助手（65）** 已获用户明确开发授权，作为独立大阶段实施；69/73 是它的导航收尾。助手不得成为绕过现有权限或候选采纳的写入入口；当前不建设费用确认/配额，但必须持久记录每次模型调用。
- **音色目录/选择体验（67）** 与 **音色/镜头布局（70）** 可一起研究，但平台允许音色仍是唯一执行白名单。
