## OVC-P5-01 关闭理由

### A. 修复了原遗漏，而不是放宽数据或权限

`backend/collaboration.py::commands` 原有节点 ID 集合变化判断被提取为 `node_identity_changed`，同时用于：

1. 原有结构锁判定；
2. 必须携带当前 graph 更新的判定。

因此，更新现有镜头内的子节点新增、移除或改名，不再因顶层 creates/deletes 为空而绕过图结构检查。缺少 graph 在写入内容、历史、审计和事件之前返回422。

携带 graph 后仍沿用排序行锁、expected_revision/assignment_epoch、完整拟提交对象状态及 graph_transition；并非只检查请求里有没有一个 graph 字段。原来对依赖边目标负责人的授权没有删除，不会自动删掉 B 的依赖或自动接管。[S02、S05]

普通正文/提示词修改不改变 node_ids，因而不新增 graph 必带要求。没有引入新的全局工程锁或把正文保存退回整份项目版本。[S05、S12]

### B. 原基线缺陷有真实应用/PG红测，修复有同路径绿测

| 入口 | 5143ee3 基线 | 34d646d 修复后 |
|---|---|---|
| 单对象 PATCH | 200；shot r1→r2；graph r4不变；拓扑悬空 | 422；shot r1和graph r4均不变；拓扑正常 |
| batch | 同上 | 同上 |
| commands | 同上 | 同上 |

测试先建立 A 负责镜头源节点、B 负责下游节点、B 合法建边，并验证 A 直接删 B 边得到403。之后经真实应用 TestClient 与隔离 PostgreSQL 执行三个更新入口。断言比较完整对象及 history/audit/events 计数，不是只断言响应码。[S06–S08]

基线结果为3 failed/15.46秒/exit1；固定业务专项为15 passed/66.21秒/exit0。它们分别保留，未把原错误行为当作应通过断言，也未把审核端此前的摘录探针替换成实施端真实PG运行。[S07–S08]

### C. 合法结构、拒绝和恢复均覆盖

`tests/test_p5_r1_structure.py` 实际验证：[S09]

- add/remove/rename 无 graph 均422；当前负责人携带正确图版本和完整结构时200，聚合文档通过 topological。
- 无效边、positions、nodeOrder、shotOrder 均422；旧 graph revision 为409。
- 拒绝请求夹带待创建节点时，所有对象及 history/audit/events 计数不变，未产生半批内容。
- 即使图已被正确清理，A 涉及 B 的目标依赖仍403，B 的边保留。
- 合法结构变更之后，单独恢复旧 shot 历史若会改变子节点身份，返回422且状态不变；历史恢复没有旁路。
- 同一 graph 的结构更新与布局更新以真实 PG 行锁形成等待，结果必须精确一200一409；对象内容、revision和记录数量随实际胜者匹配。

正式专项等待轨迹含 PID26272被38296阻塞、PID6544被26272阻塞；释放后结果为[409,200]。本轮据此认可实际竞争与完整提交断言，不把一次运行描述成穷举全部交错。[S08–S09]

### D. 前端无须为本缺陷额外改版

新增 CollaborationClient 测试实际调用拆分、差量与 save：add/remove/rename 均向一个 commands 请求提交 shot 与当前 graph revision，没有使用代码字符串检查代替请求断言。传输是可控 mock，并非浏览器/真实HTTP；本轮准确保留这个边界。[S02]

由于前端运行时未变、原合法操作已带图，符合原P5-R1提示词允许的不重做61+17次浏览器条件。原P5双用户、Twick、FFmpeg浏览器材料仍只属于原运行，不标成本轮重跑。无新增浏览器补证阻塞。
