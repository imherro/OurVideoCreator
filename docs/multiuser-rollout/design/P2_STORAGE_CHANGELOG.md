# P2 PostgreSQL 存储变更说明

## 1. 结论与边界

P2-PG-01 将所有保留业务数据的唯一运行时数据库切换为 PostgreSQL。Web 与独立 Worker 必须通过 `OVC_DATABASE_URL` 连接同一数据库；运行时没有 SQLite 回退、双写、旧库导入或按数据目录选择数据库的入口。媒体文件仍存放在私有文件目录，但媒体目录不参与数据库隔离，也不能绕过同库单 Worker 约束。

- 被测试业务 SHA：`a6820b045123ed73953cbe5667821225f8ceafb5`。
- 支持并实测：PostgreSQL 18.6。
- 驱动与迁移：SQLAlchemy 2.0.50、Alembic 1.20.0、psycopg 3.3.5；精确版本见根目录 `requirements.lock.txt`。
- Schema head：`0001_postgresql_baseline`。
- 启动契约：运维先执行 `python -m alembic upgrade head`；Web/Worker 启动只做连接与 head readiness 检查，不执行 `create_all`、`ALTER`、`DROP` 或自动迁移。
- 数据重置：没有启动时自动清库，没有面向用户数据库的 reset；测试清理只允许当前会话创建且名称匹配 `ovc_test_*` 的数据库。

## 2. 配置、连接与日志安全

`backend/database.py` 是统一数据库入口。`OVC_DATABASE_URL` 缺失、不是 PostgreSQL 或没有数据库名时立即失败；`postgresql://` 会规范化为 psycopg dialect。SQLAlchemy engine 负责 readiness 与迁移集成，业务事务使用 psycopg 显式连接。连接池启用 pre-ping，SQLAlchemy 隐藏 SQL 参数。

诊断只允许输出 `postgresql://host:port/database`、server version、database、schema 与 backend PID。`redact_database_url()` 会把用户名后的密码替换为 `***`；健康接口不返回 DSN、用户名、密码或端口。`backend.instance_identity` 将安全数据库身份纳入实例摘要，因此相同媒体目录连接不同数据库时不会被误认为同一实例，摘要本身不含凭证。

业务中的 Episode 继续物理映射为 `projects`，作品映射为 `productions`。时间字段保留现有 Unix seconds `DOUBLE PRECISION` API 语义，标识符保留文本格式，复合业务文档使用原生 `JSONB`。

## 4. JSONB 边界

共 21 个 JSONB 列：

- 业务设置：`settings.value`。
- 作品/剧集/修订：`productions.shared_context`、`production_revisions.shared_context`、`projects.document`、`revisions.document`。
- 原著与改编：`source_documents.metadata`、`source_events.characters`、`source_events.continuity`。
- 剧本：`episode_scripts.source_chapter_refs`、`paywall_beat`、`characters`、`scenes`、`props`、`metadata`，以及 `episode_script_revisions.snapshot`。
- 任务与事件：`jobs.input`、`jobs.result`、`jobs.telemetry`、`job_private.provider`、`events.payload`。
- 素材：`assets.metadata`。

psycopg 在读取 JSONB 时保持既有字符串序列化边界，避免在本阶段改变 API payload；数据库物理类型仍为 JSONB，可在后续阶段安全增加结构化查询。

## 5. 事务、并发与任务领取

- 剧集/作品保存先 `SELECT ... FOR UPDATE`，再以旧 revision 为条件更新。同一 revision 的两个并发请求只能一个成功，另一个得到 409；内容、revision history 与 event 在同一事务提交。
- 批量任务创建把每个 `jobs`、`job_private` 和对应 event 放入一个事务；最后一项注入失败时整批回滚，不留下前序半成品。
- Worker 使用 `FOR UPDATE SKIP LOCKED` 选择 queued 任务，并用条件更新完成 claim；任务状态、Provider 私有映射与结果继续遵循原状态机。
- P2 仍只有一个 Worker。Worker 在同一业务数据库上持有固定 key 的 PostgreSQL session advisory lock，锁连接独立且贯穿 Worker 生命周期。锁由数据库而不是 `MVC_DATA_DIR` 决定，因此换媒体目录不能启动第二 Worker。
- Web 不持有 Worker lock；两个 Web 可共享数据库。Web 重启不取消正在执行的任务。

## 6. 文件存储边界

`backend/storage.py` 新增 `StorageBackend` 抽象和当前 `LocalStorageBackend` 实现。新素材写入与 API 读取通过该边界解析私有路径，并拒绝目录穿越。P2 不迁移既有媒体、不引入对象存储，也不把文件目录当数据库身份。后续对象存储替换可以在不改变业务表主键与 API 资源身份的前提下实现。

## 7. 迁移、测试与已退役路径

- 唯一建库路径：独立 Alembic；空库 `upgrade head` 和重复执行均成功。
- `store.init()` 只调用 readiness，精确检查 PostgreSQL dialect 与 Alembic head。
- pytest 每次会话创建唯一 `ovc_test_<pid>_<random>` 数据库，先迁移再收集测试；只终止并删除该会话创建且命名匹配的库。
- `Stop-Studio.ps1` 只依赖本地生命周期记录，数据库离线时仍可证明并停止自己的进程。
- PowerShell 5.1 与 7 均按 project root、data dir、PID、UTC creation ticks、executable 与完整 command line 校验所有权；不会因 JSON 日期自动转换丢失精度。
- 已删除 `backend/model_migrations.py` 与 SQLite 启动迁移；运行时代码、迁移、脚本中没有 `sqlite3`、`PRAGMA`、`AUTOINCREMENT`、`INSERT OR REPLACE` 或 SQLite 文件路径。测试中仅保留负向断言字符串，证明 SQLite DSN 会失败。
- 本阶段不复制旧 SQLite key、不导入旧库、不双写，也不提供 SQLite runtime option。

## 8. 阶段限制

P2 未实现 P3 身份/ACL、P4 凭证加密、P5 多 Worker lease/fencing/quota、P6 对象级协作 API、P7 公网部署与 P8 总体验收。真实付费 Provider 未调用；Provider 契约使用 monkeypatch、本机 fake server 和禁止非 loopback 出站的测试复验。
