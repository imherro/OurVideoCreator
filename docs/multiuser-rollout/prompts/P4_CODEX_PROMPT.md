## 一、不可改变的产品边界

所有供应商、API Key、可用模型由平台管理员统一配置。Workspace owner、production manager/editor/viewer 和普通账号都不能自带、读取或管理平台 Key，也不能改上游 URL/headers/凭证。普通用户只选择平台发布的安全模型目录，并在既有作品权限范围内使用。

保留邀请制账号、未验证手机号登录名、自设密码、团队及作品 ACL、私有素材授权、SSE 过滤和单 Worker。继续外部 API-only，不恢复内置推理。未来自托管推理仍作为显式受控的外部 Provider 接入，不实现本地 GPU/权重/进程管理。

不要做 P5 对象协作/租约，不做 P6 多 Worker、计费、配额调度或队列重写，不做充值、积分、支付，不做公网发布或容量承诺。不以微服务、Redis、Kubernetes、Vault/KMS/HSM、全新插件平台作为本轮前置。现有模块化单体、PG、独立 Worker 足够。

旧测试数据和旧 Key 不需迁移；不要为了历史兼容做双写/回落，也不要在正常启动、迁移时无条件清库或扫描重写全部业务。需要测试重置时只使用显式白名单、隔离库/目录。

## 三、数据库与密钥：唯一受控来源

用增量 Alembic migration 建立以下职责的实体（具体命名/合理合并由现有代码决定）：

- Provider 配置：类型、名称、服务地址、必要的非秘密参数、启停、版本/审计。
- Provider 凭证版本：所属 Provider、加密密文、密钥版本标识、当前/退役/吊销状态和审计元数据。
- 模型目录及版本：平台 model_id、Provider 引用、上游模型标识、文本/图片/视频/语音用途、展示信息、能力、默认参数、允许参数规则、发布/启停与默认选择。
- jobs/job_private 仅增加必要的模型版本、Provider 配置版本/凭证版本引用，以及非秘密参数快照。

不要求把所有现有 JSONB 拆成列或引入通用规则语言。常见长度、枚举、数量、时长、分辨率、token 上限等用简单、可读的服务端规则即可。

使用成熟认证加密库保护 Key。主密钥通过部署 secret/进程环境提供，不放 Git、不与密文同表存明文、不派生自公开常量、不每次启动生成。开发/测试可显式生成临时独立密钥。无需接外部 KMS。

缺少/错误主密钥或损坏密文时，涉及凭证的保存/解密/模型调用必须明确失败且不出站；不得回落明文、旧 settings 或自动再生新密钥覆盖。允许账号管理/健康页仍可用，但要明示模型服务不可用，不能伪装配置成功。

Key 录入后只返回“已配置”、必要脱敏标识及版本，不设普通明文回显/下载接口。更新配置时清晰区分保持原 Key、替换 Key、吊销旧版本；字段省略不应意外擦除凭证。

配置变更与必要审计原子提交；成功响应不能对应一个缺失凭证/半写目录。凭证、审计 payload 与错误响应中不得出现原始 Key。

## 四、后台与普通用户页面必须真实接通

在现有 /admin 扩展平台模型管理，而不是创建另一套登录系统。最小操作闭环：

- 创建/编辑 Provider，录入/替换凭证、启停、检查配置。
- 新建/编辑并发布模型，配置用途/上游标识/默认参数/允许范围/必要能力，选择各用途默认模型。
- 管理员看到明确保存、冲突、验证和启停状态；错误由真实接口反馈。
- 普通用户在现有创作页面只看到安全目录，只能选择发布且可用的模型；无可用模型时显示明确空状态，不自动回落本地或其他付费模型。

服务端检查平台管理员身份及 CSRF，不只隐藏按钮。owner/manager/editor/viewer 直接请求新旧管理 API 都要拒绝。

模型目录是普通使用入口，不允许普通成员手填 endpoint、API Key、Authorization、任意 headers 或真正的上游 model 标识。既有普通 /api/settings 仅保留需要的安全投影；旧 Provider 写入、verify/test 等入口要退役或转到同一受控服务，不能成为第二个权威写入点。

保持既定“平台级提示词库仅管理员写、普通用户读”的边界，回归 P4-TPL-01；不另建提示词 CMS。

## 五、从页面选模型到 Worker 执行只走一个安全解析流程

普通任务提交以平台 model_id 为唯一模型选择。可提交与内容有关的提示词、参考素材 ID、允许参数等，但必须由服务端：

- 校验用户当前作品权限、模型可用性、用途及参考图/首尾帧/音频等必要能力。
- 校验并规范化参数，拒绝隐藏嵌套的 Provider/Key/URL/header/上游模型覆盖；不能只删外层同名字段。
- 解析并固化所选模型版本、Provider 配置与凭证版本引用。
- 批量先验证全部项再原子入队，不能前半批已经创建任务、后半批才拒绝越权配置。

覆盖所有实际入口：普通单节点、批量、原著提取、改编/剧本生成、视觉/语音/视频、剪辑导出中适用的生成路径、恢复原任务及旧整份 document 中的节点配置。不要只改一个 POST /jobs。

业务文档里可以保留无害的展示性旧字段，但它们绝不能决定实际 endpoint/Key/headers。不必为旧测试工程写兼容迁移；新 UI 直接使用新模型目录。

Provider adapter 继续完成各自协议，仅从受控服务临时获得解密配置。明文只在服务端必要调用期间使用，不复制进 input/result、job_private JSON、历史、SSE、导出或前端 network 返回。

保留既有 Provider 已接通能力和契约，包含 OpenAI-compatible、Ark、语音、RunningHub、幻场、Replicate、MiniMax、ComfyUI、Maestro 等的实际基线能力，不承诺上游理论支持但本项目未接通的功能。FFmpeg/ffprobe、素材、Twick 不是推理，不能误删。

## 六、最小凭证/模型版本规则

新提交的任务使用当前启用版本；已接收任务保留提交时的版本引用，不在执行/恢复时悄悄重绑到另一账号或 URL。正常 Key 轮换与旧凭证吊销分开：

- 正常轮换：新提交用新凭证，已有远端 handle 的查询/取消继续用其原凭证与地址。
- 旧版本吊销/不可用：旧任务明确显示受阻/待核对，不拿新账号尝试查同一远端 ID，更不能自动重新发起生成。
- 模型/Provider 停用：停止新提交；排队且尚未出站的任务执行前也不得绕过停用继续新调用。已提交远端任务是否仍可查询，按明确的“停用新调用”和“吊销凭证”规则处理。
- 模型参数/地址变化也应固化必要配置版本或非秘密快照；不能只固定 Key 却把恢复请求发往最新另一个地址。已被任务引用的版本不得被无提示硬删除。

这些只是在现有单 Worker 中保住配置身份，不要实现 P6 全套 lease/fencing/quota/远端 exactly-once。

## 七、连接检查与出站边界

“保存成功”“格式校验通过”“免费鉴权成功”“实际生成验证”必须区分。检查按钮默认不能偷偷提交生成、扣费或上传真实素材。没有免费检查协议时，如实显示未验证；不能用静态模型清单伪造“API Key 鉴权成功”。本轮所有验证走 fake/契约，真实费用未授权。

集中实现小型 URL/出站策略，覆盖 Provider base URL、结果下载、引用 URL 和 redirect。默认拒绝凭证内嵌 URL、非 HTTP(S)、loopback/private/link-local/metadata 等目标；域名解析和重定向后目标也需检查，不能只检查最初字符串。不要把平台认证 header 自动传到任意结果 URL/异源重定向。

本地 fake 及未来私有推理服务采用管理员/部署明确配置的窄范围 host/IP/port 例外，不是一个“关闭所有 SSRF 检查”的开关。真实上游 hostname 不需枚举全世界白名单；遵守既定公共目标规则，测试用 fake resolver/transport 和确切 loopback 例外即可。

保留幻场远端素材登记/审核/映射；作用域至少保持资产作品/团队边界和正确 Provider 账号配置身份。不能因全平台共用 Key 而让无权用户复用别的作品素材。内部计算摘要或版本映射不等于可向普通用户暴露 Key。
