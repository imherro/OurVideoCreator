# P1 本轮失败与修正记录

以下是开发期间真实出现的失败。最终原始复跑日志见同目录 `01`–`10` 文件；中间探索性运行当时没有重定向保存，不能事后伪造原始 stdout。

| 顺序 | 运行 | 首次结果 | 原因 | 修正与复跑 |
|---|---|---|---|---|
| 1 | `npm test` | 120 通过、3 失败 | 移除隐式 Provider 回退后，节点初始化测试仍假定自动获得本地模型 | 新节点在没有项目策略时保留空 Provider/模型，真正提交时明确报配置错误；随后 123/123 通过 |
| 2 | `pytest -q tests/test_p1_processes.py -s` | 失败 | Windows 子进程输出按系统 GBK 解码，而 Worker 明确输出 UTF-8 | 为捕获调用指定 UTF-8，并在进程环境设置 `PYTHONUTF8=1`；随后通过 |
| 3 | API/项目定向回归 | 3 失败 | 旧测试用例仍创建 `provider=local`，或在同一隔离库残留无关 queued job | 测试改用显式外部假 Provider，并在 Worker 定向测试前取消无关任务；随后 42/42 通过 |
| 4 | `pytest -q` | 245 通过、6 失败 | adaptation/source-library 旧夹具仍提交 `provider=local`；能力错误文案仍断言旧“本地未安装”措辞 | 两个模块配置显式外部测试网关，能力断言改为 Maestro API 不可用；随后 251/251 通过 |
| 5 | 最终证据前 UI 检查 | 无运行失败 | 原测试只间接覆盖默认 UI，证据不够直接 | 新增 `tests/p1_surface.test.mjs`，直接约束推理目录/runtime 路由和旧本地模型控件不回归；最终前端 125/125 通过 |

没有通过删除有效功能测试来消除失败。删除的两个 Python 测试只验证已经退役的内置目录自动启动和本地默认模型；替代证据是 P1 表面测试、双 Web/独立 Worker 进程测试及无 Provider 零出站测试。
