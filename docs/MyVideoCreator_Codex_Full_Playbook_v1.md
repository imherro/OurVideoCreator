# MyVideoCreator 多用户改造：Codex 实施与验收工作包

版本：1.0 · 2026-09-16
仓库：imherro/MyVideoCreator
本轮核验基线：464914c553f4c1856ca77da4a07e9d5fffb7f71e（简称 464914c5）。
本包是开发指令与验收规范，不是已完成的代码、测试报告或安全认证。

## 使用流程

把压缩包里的 `docs/multiuser-rollout/` 放进仓库同名目录。它只添加文档，不应覆盖业务代码。
在 Codex 中首先发送下面的启动指令，第一轮只执行 P0：

```text
你现在负责 imherro/MyVideoCreator 的多用户改造。
先读取 docs/multiuser-rollout/prompts/00-controller.md 和
 docs/multiuser-rollout/01_CONTRACT.md，再读取
 docs/multiuser-rollout/prompts/P0-baseline.md。
本次只执行 P0。先核对实际 HEAD、工作区改动和仓库已有 AGENTS.md。
不能回退或覆盖用户的新提交；计划基线 464914c5 只是已知参考，不是强制 checkout 目标。
请产出 P0 指定文档和真实基线测试证据，停止在 P0 待验收状态。
不要开始 P1，不要调用真实付费 API，不要清理测试数据库以外的文件或资源。
完成后按 docs/multiuser-rollout/03_EVIDENCE_TEMPLATE.md 交付提交信息和证据。
```

P0 验收通过后，下一轮发送：

```text
上一阶段已由外部验收人通过；通过的提交和结论见下面粘贴的验收记录。
读取 docs/multiuser-rollout/prompts/00-controller.md、01_CONTRACT.md、
02_ACCEPTANCE_MATRIX.md，以及 prompts/P1-cloud-only.md（均位于 docs/multiuser-rollout/）。
仅执行 P1，禁止跨阶段。按交付模板提供代码、测试和证据；完成后停止，等待外部验收。
[粘贴上一阶段的验收结论与通过 SHA]
```

后续替换阶段提示词路径即可。不要把九阶段全文一次交给 Codex 并要求“一口气完成”。
每阶段推荐一个独立 PR；也可使用同一开发分支上可核对的 base/head 提交区间。每个阶段可以有多个小提交，但不混入下一阶段。无 GitHub 写权限时只产出本地提交和补丁，不虚构 PR。

## 阶段顺序与关口

| 阶段 | 提示词 | 交付重点 | 外部验收关口 |
|---|---|---|---|

## 谁负责什么

Codex：实现、添加测试、复现缺陷、执行自测、整理可核对的证据。
外部验收人（本对话中的 ChatGPT）：按你提交的 PR/SHA 读取实际变更和相关代码，核验测试日志，针对关键路径复测或给出补充测试，再作阶段/整体结论。
你：把每阶段交付的 PR 或 SHA 发到本对话，批准下一阶段，录入密钥并授权必要的真实付费测试。

这里没有后台自动监控、自动审批或自动启动下一阶段。每次验收在收到相应提交后的对话中进行。
Codex 的自评不能充当外部验收；截图不能充当越权和并发正确性的证明。

## 结论语义

- 通过：该阶段范围内没有阻塞问题，规定证据齐全；允许进入下一阶段。
- 不通过：有可复现缺陷或偏离契约；给出问题编号和返修项。
- 证据不足（阻塞）：环境、日志或关键运行结果缺失，不能确认通过。

发布结论再分开写：代码集成是否通过、小团队部署是否通过、哪些供应商真实 API 已验证。
没有真实供应商试运行时，可以认可软件集成通过，但不能写“全部商用 API 已验收”。

# 文件 2：01_CONTRACT.md

# 冻结的第一版产品与技术契约

本契约来源于用户已经确认的需求，以及为减少反复询问而采用的第一版默认规则。
实现细节可以在不改变行为的前提下调整；改变权限、归属、计费语义、协作粒度或范围，必须先提交差异说明，不得自行扩展。

## 1. 已明确的产品边界

面向小团队，用户由邀请注册，手机号是登录名、自设密码、无短信。没有历史数据迁移要求。
团队内不同人负责不同对象；不做同段文字实时共编、CRDT、在线光标、复杂组织树或自定义权限编辑器。
所有供应商、API Key 和可用模型由平台管理员在专用后台统一维护；普通用户、团队负责人均只能选用发布的模型，不能自带 Key 或填任意网关地址。
去除本仓库内的模型安装、权重管理、GPU 探测/加载、推理进程管理及对应前端入口。未来独立推理服务作为外部 API 接入，不在本次开发其服务端。
保留外部云端 Provider、原著/剧本、Film Bible、分镜、参考素材、生成版本、任务、画布、剪辑和 FFmpeg 导出。
移除旧数据兼容，不等于移除新系统的内容版本、审计、错误恢复和备份能力。

## 2. 基线与不误删要求

2026-09-16 已核验 master 为 464914c553f4c1856ca77da4a07e9d5fffb7f71e。
该提交新增幻场供应商素材组/素材登记与持久映射。P0 必须纳入回归清单。
每轮先读取实际 HEAD；更新于该基线的代码必须审查保留，不能 git reset 回旧提交。
现有 src/main.tsx 和 backend/app.py 承担大量功能，优先按本阶段边界抽模块，不整体换 UI 或大规模格式化。
旧库、旧素材和 inference 内项目专属测试文件允许清理，但必须是显式开发重置命令：先列出绝对路径、验证数据目录标记、拒绝根目录/仓库外路径/生产环境。不得把自动删库放进应用启动；不得全局 docker prune、清除用户其他工程或改写外部硬链接文件内容。

## 3. 简化的组织与权限模型

工作空间 Workspace 对应前端“团队”，是租户隔离和业务资产归属边界。
全局用户 User 可加入多个 Workspace。手机号仅是唯一登录名；所有业务关系用不可变 user_id。
Production 对应“作品/剧集”；现有 projects 语义是 Episode/分集，可保留物理名称，不要再造平行的 Project 概念。
作品和素材属于团队，不属于成员个人。创建者、编辑者和任务发起者只是操作人。

默认角色：
- 平台：platform_admin / user。
- 团队：owner / member。只有平台管理员建团队和指定/变更 owner。
- 作品：manager / editor / viewer；团队 owner 具有团队内作品管理能力。

默认行为：
- 平台管理员签发注册邀请、停用全局账号、管理模型和全局配额；跨团队内容访问使用显式、审计的后台入口，不在所有普通查询中隐式绕过授权。
- 团队 owner 管理本团队已有账号的成员关系，创建作品、指定作品 manager。普通成员不能列举全站用户或手机号。
- manager 管理作品成员、对象分配、审核、作品共享设置和分集结构；不能越过团队成员关系把外人直接加入作品。
- editor 可以查看参与作品的内容、评论、创建允许的工作对象（初始归自己），编辑/生成自己负责的对象。manager/owner 修改他人对象须显式接管，产生审计并使旧编辑凭证失效。
- viewer 只读，可评论，不编辑、不发起生成、不删除内容。
- 同作品的剧本、镜头、素材默认可读；同团队但未参与的其他作品不可读。不同团队无默认共享。
- 暂不做跨作品公共素材库。素材可在同一作品下跨分集引用；删除来源分集不能使仍被合法引用的作品素材失联。
- 未分配对象只允许 manager/owner 分配；成员移除时撤销其编辑权/租约、保留成果并将其对象标为待重新分配。
- 删除/恢复、版本还原、任务取消、批量操作、导出和通知遵循同一权限边界。
- 保留最后一位有效平台管理员、最后一位团队 owner；关键管理动作有防误操作和审计。

## 4. 注册、登录、账号恢复

邀请码：随机不可猜、一次性、有有效期、可撤销；数据库只存令牌摘要。邀请与账号建立在同一事务中消费，并发兑换只能一人成功。注册失败不应吃掉邀请。
手机号：服务端规范化、唯一约束；前端默认国家码可配置（首版 +86），不能仅靠客户端正则。phone_verified_at 初始为空，文案不得暗示已验证手机号归属。
邀请只授予注册资格，注册不因手机号或邀请备注自动得到团队/管理权限。注册后允许显示“等待加入团队”。入组由负责人对具体 user_id 确认。
昵称用于团队内展示；手机号仅自己及必要的后台管理可见，普通成员列表脱敏或不返回。
密码使用成熟 Argon2id 实现，最低参数参照官方安全建议并压测；允许长密码/口令短语，不明文、不可逆加密密码。密码策略第一版建议 15–128 字符，不用苛刻字符组合规则。
使用服务端可撤销随机会话 + HttpOnly Cookie，不强制 JWT；会话摘要存库并关联 user_id。生产 HTTPS、Secure、SameSite，并有 CSRF 防护和可信代理配置；不能只隐藏前端页面。
按账号与 IP 控制登录/兑换/重置尝试，状态存数据库或共享层，不能只依赖单进程字典。错误响应避免无必要泄露账号存在性。
初始管理员由显式 CLI/安全初始化流程创建，不保留互联网“首位访问者设密码”的 setup 接口；没有默认密码，重复初始化不得重置已有管理员。
密码恢复：平台管理员线下核对后签发短期一次性重置链接；用户自己设新密码，撤销旧会话。团队 owner 不能重置用户全局密码。

## 5. 数据与协作的权威来源

选用 PostgreSQL、SQLAlchemy（ORM/Core 均可）、Alembic；不保留运行时 SQLite 兼容分支。
新库从零建表，后续结构变更仍要版本化；应用启动不执行全库数据扫描迁移，不自动清库。
授权/筛选/独立协作的对象关系化；灵活结构保留 JSONB。不能只把原 document 从 TEXT 换成 JSONB。
建议实体集合（最终名称可在 P0 映射）：
users/sessions/invitations/password_reset_tokens/workspaces/workspace_members/production_members；
productions/episodes/episode_scripts/source_documents/source_chapters/source_events；
shots/visual_cards/visual_versions/editor_timelines/graph_nodes/graph_edges；
assets/content_revisions/comments/edit_leases/audit_events/domain_events；
providers/provider_credential_versions/model_catalog/model_versions；
jobs/job_attempts/quota_reservations/quota_counters/usage_events/provider_asset_mappings。
不要求为了凑表全部新建；可复用现有语义，禁止多个表同时存同一字段作为可写主数据。
租户表有明确工作空间归属；父子关系用约束/复合外键或等价机制防止跨租户、跨作品混搭；金额/计数用合适精度，时间用时区明确的时间戳。
第一版可采用服务层授权 + 强制作用域的数据访问层 + 数据完整性约束，不强制 RLS。若实现 RLS，必须测试真实应用角色、连接池复用、事务级租户上下文及显式管理路径，不能假设开启策略即安全。

保存粒度：
- 一集剧本：一个对象、一个负责人、一个 revision。
- 一个镜头：一个对象；其附属生成节点的业务编辑权继承镜头，避免双重归属。
- 一张角色/场景/道具资产卡：一个对象；已锁定视觉版本不可原地修改。
- 一集剪辑时间线：一个对象，独占短期编辑租约。
- 独立自由节点：有明确对象归属；共享图连接/排序/作品总体设定使用自己的小范围 revision，由 manager 或有明确结构权限的人维护。
- 原著/章节、导演台等现有编辑入口也必须有对象和权限映射，不能只覆盖四个新页面、遗漏旧入口。

对象修改必须在同一短事务内检查权限、版本/租约并写入数据、作者和版本历史；UPDATE ... WHERE revision=expected_revision，更新失败显式 409。不能在冲突后自动用最新版本号重发旧内容。
租约使用服务端 owner、expires_at、token/epoch；续租、过期、撤销、管理员接管都要校验。旧 token 的迟到保存/续租不能成功。普通镜头/剧本可用 revision，复杂时间线必须有租约；manager 接管需要使原持有者旧写凭证失效。
内容状态为进行中/待确认/已完成，审核确认绑定具体 revision。修改已确认内容须形成新版本并回到进行中；无每次生成强制审批。
Project.document 可作为只读聚合视图喂给既有纯函数/UI，但协作对象不能再通过整份 PUT 写回；旧批量写接口要退役或转成逐对象、逐权限、逐 expected_revision 的原子命令，不得保留旁路。
视窗、选中项、播放头、面板开合等个人 UI 状态与共享业务文档分开。

## 6. 平台模型后台

专用 /admin 管理区与受限管理 API，至少用户/团队、供应商/密钥、模型目录、任务/用量四类页面。
普通用户只获得安全模型目录：平台 model_id、用途、允许参数、能力和启用状态；不获得 Key、任意基础 URL、内部凭证快照。
提交按平台 model_id 解析。服务端拒绝覆盖 base_url、api_key、provider、任意上游模型 ID、任意 headers/模板字段；嵌套输入、批量入口也不能绕过。
输入参数做类型、枚举、数值范围和能力校验；没有可用模型时显示明确配置提示，绝不回退到本地或其他付费模型。
凭证可逆加密存库（例如成熟库的认证加密），加密主密钥用部署 secret 单独保存。没有解密钥不能静默重生导致旧凭证不可用。返回值、异常、日志、任务、导出文档不含明文 Key。
凭证轮换保留受控版本引用：任务绑定模型/配置版本及凭证版本；恢复已有上游任务不换账号。明文不能复制到 job_private。停用新调用和吊销凭证是不同动作，应提示对在途恢复的影响。
验证 Key 默认只做无生成的检查；供应商没有免费验证接口则写明“未验证”，不得用付费生成冒充免费检查。
所有 Provider/下载地址实施出站地址策略、超时、大小限制和重定向校验。未来管理员显式登记私有推理地址可走窄范围 allowlist，不得因此全局允许任意内网/云元数据访问。
保留基线的外部 Provider 契约与能力，包括幻场素材登记流程。远端素材映射以供应商账号/凭证身份 + 本地租户/素材归属等必要维度隔离；不能仅使用本地线程锁作为多 Worker 去重方案。

## 7. 任务、费用与恢复

Web 负责鉴权、验证、预占配额、持久化任务并及时返回 job_id；独立 Worker 调用模型、下载媒体或执行 FFmpeg。两者可单机部署，但生命周期独立。
PostgreSQL jobs 表作为首版持久队列；短事务领取任务，不能持有事务跨越网络等待。P6 起需能运行两个独立 Worker 验证正确性。
领取采用 SKIP LOCKED 或经测试的等价机制，附 worker_id、lease_expires_at、heartbeat、attempt/fencing token。
明确区分本地未发送、正在提交且接单状态不明、已获得 provider_job_id、远端进行中、结果待登记、终态。
数据库 fencing 只能约束本地状态写入，不能声称能撤回已发出的网络副作用。供应商不支持幂等且提交结果不明时，转待核对，不自动重新 POST。
同一请求幂等键应按工作空间+用户+入口命名空间约束，绑定规范化有效输入 hash；同键同输入返回同任务且不重复占额，同键不同输入 409，不能跨人/跨租户拿到他人任务。
任务输入冻结实际剧本/镜头/视觉版本、参数和模型版本；结果成功先成为生成记录/候选。若当前对象版本变更、负责人更换、租约变化，禁止自动覆盖人工新内容。
用户/团队/模型停用和权限变更后，新付费步骤应停止；已付费在途任务由系统身份尽可能继续查询、归档、核对费用，不能只因提交者退出就丢弃已付费结果。不能擅自再发新付费步骤。

额度与资源控制：
- 平台、供应商账号、团队、用户的并发上限；导出有独立 CPU 槽位。
- 用户/团队排队上限。
- 按文本、图片、视频、语音分类的每日提交额度；按实际规划的付费子调用计入，不能把双遍分镜/批量任务伪装成一次。
- 模型参数上限；平台/供应商一键暂停新提交。
- 公平调度至少确保一个团队的大积压不会长期饿死另一团队的合法任务。

首版额度是“每日提交额度”，不是金额预算：配额日使用后台配置时区（默认 UTC），计入成功接纳任务时的配额日；跨天保留原预占记录，排队有可配置最长寿命（建议 24 小时）以免长期滚存。UI 明确该语义。
预占与建任务在同一事务；并发请求不能超卖。幂等重发不占两次。明确未送上游的取消/失败释放预占；已发送、已受理或状态不明不自动返还提交额度，避免失败刷量。人工调整须记录原因、操作者和对账关联。
对无法预估的新增付费子步骤，执行前追加原子预占或暂停；不能先调用后补记。
本地执行槽位和远端在途计数分开，Worker 失联/用户点取消不能无条件释放仍可能运行的远端并发名额；状态未知保守计数并有管理员核对入口。
不得承诺端到端 exactly-once。实现本地幂等、可恢复状态机、迟到写入防护及不盲目重复付费。

## 8. 素材、事件与安全

单机起步采用私有持久卷 + StorageBackend 抽象。数据库存 asset_id、workspace/production 归属、key、类型/大小/hash、来源，不把可过期访问 URL 当资产身份。
Web/Worker 共用挂载卷；路径不得由用户直接控制。上传临时文件校验后原子落盘，登记失败有回收路径；同一次任务重试不重复登记。
上传/下载/Range/缩略图/导出/回收站/历史版本逐资源授权；文件内容和图片像素/媒体长度限制、防路径穿越、无 shell 字符串拼接执行 FFmpeg。
供应商读素材使用短期签名 capability 或供应商要求的安全上传；签名只允许指定文件/方法/用途，验证过期和撤销语义。不得开放整个 data/assets 静态目录。
SSE 使用事件表，按当前用户的真实作品权限过滤，重连游标和保留窗口明确；游标过旧提示完整重同步。写业务和事件尽量同事务；推送不作为唯一事实来源。
权限撤销后停止推送/继续下载的新请求；长连接定期复核会话和授权，默认最多 5 秒复核一次。已完成传输的数据不宣称可撤回；已签发外部 capability 的有效期是单独风险边界。
不引入 Redis 为前置条件，SSE 轮询可用于小团队，但要测试不会阻塞事件循环/耗尽连接池。

## 9. 部署、测试与发布范围

开发/生产使用锁定且受支持的 Python、Node、PostgreSQL、依赖版本，P0 核实；不要为“最新”全面升级无关依赖。
建议单机 Docker Compose：反向代理、Web、Worker、PostgreSQL、私有媒体卷。数据库不暴露公网，无需 Kubernetes/微服务/Celery/Redis 前置。
P2 起集成测试用真实 PostgreSQL，不能以 SQLite 代替；并发测试跨真实独立连接/进程，不能只在线程里模拟顺序调用。
浏览器测试用多个独立上下文验证不同账号和对象保存，不把源码字符串断言或 mock-only 端到端当成完整验证。
默认测试出站到付费供应商被阻止，用可编程测试 Provider 验证超时、已接单丢响应、429、重复结果、素材回调、取消等场景；测试 Provider 只能在测试环境启用。
P7 小团队验收负载默认 3 团队、30 在线会话、10 活跃编辑者、15 分钟稳态，真实 PG/Web/Worker，供应商模拟。普通轻量 CRUD p95≤500ms，非预期 5xx/网络错误率<1%，业务通知 p95≤5秒，无数据丢失/越权/额度负数/死任务。报告硬件、数据量、采样与延迟分布。这是验收目标，不是现有性能结论。
300 在线只做可选探索测试，不影响首版范围，也不能从模拟供应商结果推断商用模型吞吐。
备份包含数据库、私有素材和独立保管的加密主密钥；恢复到隔离环境，恢复时默认暂停新付费调用，先核对在途任务再恢复服务。
