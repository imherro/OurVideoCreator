# 跨集分镜复用作品视觉资产

分镜和镜头属于当前制作集；视觉角色、状态、场景、道具、版本历史和角色声音身份属于整个作品。协作版生成下一集分镜时复用 Production 的共享视觉对象，不在浏览器中覆盖或合并整份 Film Bible。

## 生成快照

- 分镜任务提交时，服务端在原对象版本锁和作品视觉绑定锁下读取所有有效 `visual_card` 对象，冻结 `storyboard_visual_context`。调用方传入的同名字段会被丢弃。
- 每张现有视觉卡都成为任务只读依赖；生成者只须拥有分镜来源对象，不会因此获得编辑其他负责人视觉卡的权限。
- 提示词只列出未删除、未弃用且父级有效的当前版本，包括稳定卡片 ID、确认别名、类型、父级、外观描述、属性、不可变约束和参考图状态。
- 明确卡片 ID 优先；否则只有名称或确认别名、类型和父级都唯一一致时才复用。歧义、类型错误和不可用父级进入原有一次修正流程，不做模糊猜测。
- 已有版本、参考图、声音和其他共享资料保持原样；模型只能提出本集确实新增的卡片或状态。

## 候选与明确采纳

- Worker 仍只保存候选，不自动写入业务对象。第二阶段分镜使用第一阶段解析后的真实视觉版本和不可变约束。
- 采纳由服务端在同一事务中完成身份、版本、状态父级、镜头绑定和对白角色 ID 映射；客户端不提交 Film Bible 覆盖补丁。
- 已有视觉对象从不作为更新写入。新卡片才由当前采纳者创建；既有卡片的负责人、revision、assignment epoch、历史、参考素材和音色均保持。
- 任务提交后任一冻结视觉对象被编辑、重新分配、删除标记变化，或作品新增视觉卡，旧候选即使请求 `accept_stale` 也不能采纳。
- 旧任务若没有完整视觉目录快照必须重新生成；不能用缺失依赖信息的历史候选写入当前共享资产库。

已删除或已弃用资产保留在历史中，但不能作为新分镜的自动复用或绑定目标。本功能不迁移旧数据库、不修改历史任务结果，也不调用额外媒体或付费 Provider。
