# 协作版直接编写剧本

## 已实现：手工正文与审核

- 网页新建作品默认“直接写剧本”，进入 EP01 剧本室；可明确选择“从原著改编”。旧 API 未传 `creation_mode` 时保持 adaptation 语义，不批量修改历史项目。
- 直接编写或粘贴正文不需要原著、事件、已批准规划或文本模型。保存进入草稿，负责人提交审核，管理者批准后从剧本室进入分镜规划。保存不是批准，也不会创建 AI 任务。
- 作品列表可继续新增集；新集继承最近未删除集的制作规格和创作起点，API 可显式选择 direct/adaptation。剧本列表包含实际集与规划集的并集，无规划的实际集也能读写。
- `episode_scripts` 仍是唯一正式正文；画布是读取投影。负责人、revision、assignment_epoch、冲突比较和历史不变。切集保留未保存正文，已批准正文发生未保存编辑时禁用本页分镜入口。
- 服务端初始化直接剧本的 `metadata.adaptationLinked=false`。无关改编规划更新不使其过期；明确引用的原著章节/事件变化仍使已审核正文过期。用户若明确采纳改编候选，恢复 adaptation 来源和依赖，不自动覆盖或采纳。
- `creationMode` 只是创作入口偏好，不是权限字段；不能通过保存正文伪造来源元数据或取消审核。

## 已实现：AI 辅助与明确采纳

- 剧本室展开“AI 辅助本集剧本”，填写本集要求，使用作品选择的平台文本模型创建一个任务；不需要原著或已批准改编规划。未保存、有冲突、未分配给自己或没有模型时不可提交。要求按作品/集保留，不串到另一集。
- 接口 `POST /api/productions/{id}/episode-scripts/{no}/assist` 接收 `instruction/model_id/revision/assignment_epoch/submission_id`（以及可选 `allow_cloud`）。平台模型解析、冻结凭证与持久 Worker 均复用原机制，不增加供应商直连入口。
- 本集正式正文、最近三个非过期非空且未删除的前集（每集末尾最多 8000 字符）、制作规格和组合后的 Bible 冻结入提示词。视觉描述以协作对象当前版本为准；显式引用的原著章节版本也是依赖。通用任务入口重新构造服务端提示词，不信任客户端伪造的 system/schema。
- 相同提交 ID 的相同输入幂等返回原任务；本集已排队/运行时不能再创建另一份剧本任务。网络结果不确定的网页重试保留 ID，明确成功后的后续生成使用新 ID。
- 生成成功只产生候选。任务中心明确采纳才写入草稿，仍需提交审核和批准；不会自动替换正文。目标修改/重新分配、上下文变化或本集已有采纳的视频时拒绝旧结果，即使请求 `accept_stale=true`。原正文来源、剧情目标与卡点保留，采纳后的来源标为 `direct_ai`。
- 提交/采纳只在短事务内锁定依赖，不在模型调用期间持锁。参考对象正被保存时返回 409，避免倒序等待产生死锁；这不是新的任务平台或全局编辑锁。
